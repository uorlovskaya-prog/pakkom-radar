# Пакком — доступ к управленческому сайту

Рабочий результат для владельца — постоянная страница `management.html`, а не очередной HTML для скачивания. `index.html` — отдельный менеджерский Radar; не заменять его финансовым дашбордом. Обновления обоих сайтов готовить из последнего проверенного полного отчёта с товарной детализацией, без самостоятельного получения данных WB через API.

## Версия доступа v10

Обновлены только вход и зашифрованная оболочка приватного ключа. Числа, даты, зашифрованный финансовый payload, публичный RSA-ключ и исправление фильтров v9 сохранены. Пользователь выбрал новый пароль в чате. Не записывать его в репозиторий, скрипты, журнал CI, сообщения коммитов или URL.

Чекбокс «Запомнить вход на этом устройстве» включён по умолчанию. Сохраняется non-extractable CryptoKey в IndexedDB `pakkom-management-access`, не пароль. Отпечаток доступа зависит от публичного ключа, соли и IV оболочки аккаунта. Кнопка «Выйти» удаляет локальную запись; простое закрытие вкладки оставляет сохранённый вход. На чужом устройстве чекбокс необходимо снять. Удаление данных сайта, другой браузер или другое устройство потребуют входа заново.

## Обязательные правила последующих обновлений

1. Всегда читать актуальный `management.html` из main; не брать старую оболочку аккаунта из архивного файла.
2. При новом отчёте сохранять весь актуальный объект `account` без изменений. Для выпуска нового зашифрованного отчёта нужен только `account.publicKey`; пароль владельца не нужен. Это также сохраняет вход на уже доверенных устройствах.
3. Не откатывать `PAKKOM_MANAGEMENT_ACCESS_V10`, `PAKKOM_MANAGEMENT_FILTERS_V9` или нормализацию SKU. Не публиковать расшифрованный финансовый HTML и приватный ключ.
4. `access-account-v10.json` содержит только зашифрованную оболочку ключа и публичные параметры. Workflow применяется ограниченно и останавливается при неизвестной версии доступа; не запускать его как универсальный загрузчик новых отчётов.
5. После записи обязательно подтвердить успешную публикацию Pages и совпадение опубликованной страницы с проверенными байтами. Сохранение файла в репозиторий не равно публикации сайта.

Проверка v10: реальный новый пароль локально расшифровывает существующий отчёт; полный обновлённый management.html побайтно совпал с проверенной копией. CI использует исключительно синтетические тестовые ключи и данные для проверки неправильного пароля, сохранения входа, перезагрузки страницы, перезапуска браузера, обновления, выхода и снятого чекбокса. Финансовые данные и реальные пароли в CI не передаются.
